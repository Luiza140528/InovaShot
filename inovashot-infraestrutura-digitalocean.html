Como o InovaShot Roda no DigitalOcean: A Infraestrutura Por Trás de um SaaS de IA Construído do Zero pelo Celular

Publicado em 6 de agosto de 2026 · Leitura: 5 minutos · Luiza Costa Soares
Ganhamos comissões quando você compra através dos links abaixo.

Toda vez que alguém descobre o InovaShot e pergunta "qual é a equipe técnica por trás disso?", a resposta surpreende: não tem equipe. O InovaShot — nossa plataforma de geração automática de clips curtos via IA, usando Whisper e Claude para transcrever, cortar e legendar vídeos — foi e continua sendo construído inteiramente por uma pessoa, pelo celular Android, sem escritório, sem time de dev, sem servidor físico embaixo da mesa.

Isso só é possível por causa de algumas escolhas de infraestrutura que priorizam simplicidade acima de tudo. Este artigo é sobre essas escolhas — o que funcionou, o que não funcionou, e por que o DigitalOcean acabou sendo a peça central de tudo isso.

Por que DigitalOcean

Antes do DigitalOcean, o InovaShot (então ainda chamado ClipMind) rodava em outra plataforma de hospedagem. Funcionava bem no começo, mas os problemas de billing começaram a aparecer conforme o uso crescia — cobranças inesperadas, dificuldade de prever custo mensal, e uma sensação geral de estar construindo em cima de terreno instável.

A migração para o DigitalOcean resolveu isso de forma direta: um Droplet (a máquina virtual deles) com custo fixo e previsível, sem surpresas no fim do mês. Para quem gerencia sozinha múltiplos produtos e não tem tempo de ficar monitorando faturas, isso é decisivo.

Se você está pensando em hospedar seu próprio projeto e quer testar o DigitalOcean, este é o link que uso — você ganha créditos iniciais para testar sem compromisso.

A stack real do InovaShot

Não tem segredo nem complexidade desnecessária. A stack inteira roda em cima de três peças:

Droplet

A máquina virtual onde tudo vive. É nela que o backend processa os vídeos: download, transcrição via Whisper, geração dos clips, scoring de viralidade.

PM2

Gerenciador de processos Node.js que mantém a aplicação rodando 24/7, reinicia automaticamente se algo cair, e organiza os logs de forma que dá pra diagnosticar problema direto pelo celular, via SSH.

Nginx

Atua como proxy reverso, direcionando as requisições que chegam pro processo certo, e cuidando do HTTPS.

É uma stack deliberadamente simples. Cada peça faz uma coisa e faz bem — nada de arquitetura sofisticada demais para o tamanho atual do produto.

Desafios que foram resolvidos nessa infraestrutura

Construir e manter tudo isso pelo celular trouxe desafios específicos que vale contar:

Diagnóstico remoto de bugs

Um dos bugs mais complicados foi na remoção de silêncio dos vídeos — o processo às vezes cortava partes que não deveria. Resolver isso exigiu instalar o Claude Code diretamente no servidor DigitalOcean e usá-lo para investigar os logs e propor correções, tudo via terminal SSH pelo celular, usando o app Termius.

Gerenciamento sem IDE tradicional

Editar código sem um computador convencional significa depender de ferramentas mobile-first: GitHub mobile para revisar e mergear código, Termius para acessar o servidor, e o próprio Claude como parceiro de desenvolvimento para escrever e revisar as mudanças antes de subir pra produção.

Integrações externas

Conectar o InovaShot com APIs como Threads e Meta Graph exigiu depuração cuidadosa — inclusive descobrir que faltava um caso de uso específico ("Gerenciar tudo na sua Página") nas permissões da Meta, algo que só apareceu depois de investigar a fundo as respostas de erro da API.

Nada disso teria sido possível de forma tão ágil sem uma infraestrutura previsível como a do DigitalOcean como base.

Lições para quem quer montar algo parecido

Se você está começando a construir seu próprio SaaS sem equipe técnica, algumas coisas que aprendi nesse processo:

  • Escolha infraestrutura com custo previsível. Surpresas na fatura tiram tempo e energia que deveriam ir para o produto.
  • Invista em ferramentas de acesso remoto confiáveis. Um bom app SSH (como o Termius) é tão importante quanto o código em si, quando você não tem acesso físico ao servidor.
  • Não superdimensione a stack. Droplet + PM2 + Nginx resolve muito mais do que parece à primeira vista — não é preciso Kubernetes nem arquitetura de microsserviços para validar e crescer um produto.
  • Documente enquanto constrói. Um CLAUDE.md e scripts de checagem de segredos no repositório fazem diferença enorme quando você é a única pessoa mantendo o contexto do projeto.
